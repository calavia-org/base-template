## Project Overview

GitHub template repository (`isTemplate: true`) used as the starting point for newly created `calavia-org` repositories. It ships the minimal scaffolding every repo needs: canonical pre-commit hooks, semantic-release automation, Dependabot, and a devcontainer.

## Repository Layout

```text
.
├── .devcontainer/
│   └── devcontainer.json          # Debian devcontainer with pre-commit + Node features
├── .github/
│   ├── dependabot.yml             # Weekly devcontainers ecosystem updates
│   └── workflows/
│       ├── pull-request.yml       # Runs the pre-commit action on PRs to main
│       ├── pre-release.yml        # Semantic pre-release on fix/** and feature/** pushes
│       ├── release.yml            # Semantic release on push to main
│       └── pr-check-and-test.yml  # Reusable PR checks via workflows-lib@v0
├── .gitignore                     # Jekyll / GitHub Pages ignore set
├── .pre-commit-config.yaml        # Canonical calavia-org pre-commit configuration
├── .releaserc                     # semantic-release config (main + fix/**, feature/** prereleases)
├── CHANGELOG.md                   # Generated by semantic-release — never edit by hand
├── LICENSE                        # GNU GPL-3.0
└── README.md                      # Minimal repo description
```

## Tech Stack

- **Language**: none — scaffolding only (YAML, JSON, Markdown)
- **Release automation**: [semantic-release](https://semantic-release.gitbook.io/) via `cycjimmy/semantic-release-action`
- **Hooks**: pre-commit (canonical org configuration, copied verbatim from `org-standards`)
- **CI**: GitHub Actions; PR checks delegate to `calavia-org/workflows-lib`

## Testing

There is no test suite — this repository contains no source code. Validation is:

```bash

```

## CI/CD

- **PR checks**: `.github/workflows/pr-check-and-test.yml` calls `calavia-org/workflows-lib/.github/workflows/pr-check-and-test.yml@v0` with build/unit/integration disabled (nothing to build). `.github/workflows/pull-request.yml` additionally runs the pre-commit action.
- **Pre-release**: `.github/workflows/pre-release.yml` cuts a semantic pre-release (`-fix`, `-rc`) on pushes to `fix/**` / `feature/**` branches.
- **Release**: `.github/workflows/release.yml` runs semantic-release on every push to `main` — bumps the version, updates `CHANGELOG.md`, tags, and publishes the GitHub release. It requires the `RELEASE_TOKEN` secret.

## Commits & Branches

- All commits follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `chore:`, `docs:` …); the commit type drives semantic-release versioning.
- Branches use conventional prefixes: `feat/`, `fix/`, `chore/`, `docs/`. Note: `.releaserc` and `pre-release.yml` currently match `feature/**` and `fix/**` for pre-releases, so use `feature/` (not `feat/`) when a pre-release is needed.
- Never commit directly to `main`/`master` — every change goes through a PR (squash merge only).

## Gotchas & Special Cases

- **This is a GitHub template repository** (`isTemplate: true`): templating is done by GitHub's "Use this template" mechanism, which copies files verbatim — there are no `.template` suffixes or `{{PLACEHOLDER}}` tokens in the tree. Repositories derived from it MUST adapt this `AGENTS.md`, `README.md`, `.releaserc`, and the workflows to their own stack (enable build/test inputs in `pr-check-and-test.yml`, extend `.pre-commit-config.yaml` with language hooks, and replace the Jekyll `.gitignore`).
- `.releaserc` pre-release branch patterns use `feature/**`, not the org-standard `feat/` prefix.
- `release.yml` authenticates with `secrets.RELEASE_TOKEN` (not `GITHUB_TOKEN`) — derived repositories must create that secret or releases fail.
- `CHANGELOG.md` is fully managed by semantic-release; manual edits are rewritten on the next release.
